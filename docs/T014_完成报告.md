## 技术实现

### API适配方案
由于前端使用新风格API（yudao-ui-admin-vue3规范），后端使用旧RuoYi风格API，采用了适配器模式：

1. **保留原有Controller**: `SysPostController.java` 保持不变，支持旧前端
2. **新增适配Controller**: `SysPostAdapterController.java` 映射到 `/admin-api` 路径
3. **复用Service层**: 两个Controller共享同一个 `ISysPostService` 实现

这种方案的优点：
- 不破坏现有功能
- 支持新旧前端并存
- 代码复用，维护成本低

## 注意事项

1. **API路径**: 前端调用的是 `/admin-api/system/post/*`，需要确保前端配置的 `VITE_BASE_URL` 和 `VITE_API_URL` 正确

2. **环境配置**:
   - 前端：`.env.dev` 中 `VITE_API_URL=/admin-api`
   - 后端：默认端口 8080，context-path: `/`

3. **权限配置**: 需要在菜单管理中配置岗位管理的权限标识：
   - `system:post:list` - 查询岗位列表
   - `system:post:query` - 查询岗位详情
   - `system:post:add` - 新增岗位
   - `system:post:edit` - 修改岗位
   - `system:post:remove` - 删除岗位
   - `system:post:export` - 导出岗位

4. **数据库表**: 使用 `sys_post` 表，确保表结构与 `SysPost` 实体类匹配
